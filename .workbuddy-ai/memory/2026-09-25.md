# 2026-09-25

## 架构重构：把 Copilot Session 降级为 Runtime 内部实现细节

**背景**：原骨架只有 React/Vite + Express + `copilot.ts` + `sessions.ts`，无持久化，
且 `Session` 被当作业务对象，会持续误导后续设计。

**结果**：按 `Member / Conversation / MemberRuntime / CopilotSession / Execution`
五层模型重写。文件结构与既定目标完全一致（server 15 个文件 + src 6 个文件），
删除 `server/routes/sessions.ts` 与 `src/components/Chat.tsx`。

### 新增/重写
- `server/domain.ts` — 五个业务对象的类型定义与边界注释
- `server/db.ts` — `node:sqlite`（`DatabaseSync`）+ 6 张表 + WAL + `foreign_keys=ON`
- `server/member-service.ts` — 长期 Member 身份，member home 落 `SOUL.md` / `memory/MEMORY.md` / `skills/`
- `server/copilot.ts` — 只负责 `MemberRuntime → CopilotSession`，含 `ask_member` / `remember_member`
- `server/team-service.ts` — 核心编排 + SSE 订阅 + delegation 守卫
- `server/app.ts` — 依赖装配（延迟箭头函数打破 CopilotService ↔ TeamService 循环）
- `server/routes/{members,conversations}.ts`
- `src/components/TeamChat.tsx`、重写 `src/lib/api.ts`、`src/index.css`、`README.md`

### 相对原始设计的 8 处修正（都是确定性 bug，不是风格偏好）
1. `streaming: true` — SDK 默认 false，不开 `assistant.message_delta` 根本不发，前端增量永远为空
2. `listMessages` 改为取**最近** N 条（原设计 `ORDER BY created_at ASC LIMIT n` 取的是最旧 N 条）
3. fire-and-forget 的 `executeMemberTurn` 补 `.catch()`，否则失败的 turn 变成 unhandled rejection
4. 新增 `config.executionTimeoutMs`（默认 10min）传给 `sendAndWait`，SDK 默认 60s 会把真实长任务判 failed
5. `ensureRuntime` 改 `INSERT OR IGNORE` + 回读，避免并发撞 `UNIQUE(conversation_id, member_id)`
6. SPA fallback 跳过 `/api/*`，未知 API 返回 JSON 404 而不是一份 HTML
7. 业务校验错误统一带 `status: 400`（原设计用裸 `new Error` → 500）
8. `errorHandler.ts` 抽出 `sendError/errorStatus/errorMessage`，消除 route 里 ~150 行重复 try/catch

### 验证
- `npm run typecheck`（3 个 tsconfig）、`npm run build` 全绿
- `npm test`：19 个用例通过（含 delegation cycle / depth / runtime 隔离 / SSE 事件）
- 28 项 API smoke test 全通过（真实启动 `dist-server/index.js`，临时 DATA_DIR，
  含 202 入队 → execution 终态 → runtime/workspace 落盘的完整异步链路）
- 无 Copilot 凭据时 turn 正确落到 `failed` 并记录错误，进程不崩

### 约定（长期）
- **不引入 ORM**（Prisma/Drizzle/better-sqlite3 都不要）。Node >= 22.13 直接用 `node:sqlite`
- **不用 SDK `customAgents` 实现 Member**。`customAgents` = Runtime 内部 sub-agent；Member = 应用层业务身份
- Member→Member 只能走宿主自己的 `ask_member` tool → `TeamService.delegateMember()`，
  保证每次协作都落 `execution.parent_execution_id` + `delegation_path`
- `delegation_path` 同时防环（A→B→C→A）和防深（`MAX_DELEGATION_DEPTH`）
- Conversation 记忆（`conversation_message`）与 Member 长期记忆（`members/<id>/memory/MEMORY.md`）不混
- 第一版 Group Chat 用确定性的 `targetMemberId`，不上 LLM router
- `coding` toolProfile 含 `bash`，无 sandbox 时不可用于多租户生产
- `local-user` 是认证占位；接 OIDC 时只改请求上下文，不动业务数据模型
