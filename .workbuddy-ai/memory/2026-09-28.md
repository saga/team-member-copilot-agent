TeamService 保留：门面（33 个一行转发）+ 共享基础设施 + `buildInternals()`。

**关键设计决策：**

1. **不把 45 个 private 成员改成 public**。四个服务不持有 TeamService，而是拿一个
   `TeamInternals` 对象。public 会让 `insertExecution` / `emit` / `transaction`
   这些内部记账变成外部可调 API，恰恰是最不该被碰的。
   `buildInternals()` 里：字段直接读引用，方法用 `bind(this)`（保留泛型签名，
   不用重写类型参数）。
2. **`team-shared.ts` 存在的唯一理由是打断循环依赖**。这些行形状/映射/常量既不属于
   某一个服务，留在 team-service.ts 又会让拆出去的服务反向 import TeamService。
   放中间层，两边都向下依赖。`ExecutionCancelledError` 也一起搬过去，并在
   team-service.ts 里 `export { ExecutionCancelledError } from './team-shared.js'`
   保住原有公开 API。
3. **四个服务彼此不 import**。跨组调用一律走 `internals`（例如 collaboration 用
   `internals.executeMemberTurn`，execution 用 `internals.getConversation`）。
   因此不存在 collaboration ↔ execution 的循环。
4. **`internals` 在构造函数末尾构建**：它按值捕获 db/states/tasks 等字段，那些字段
   在构造过程中才就位。
5. **private 方法搬走后 TeamService 的转发仍保留 private**（runWake /
   executeMemberTurn / buildConfigSnapshot）—— 不然等于顺手扩大了公开 API。

**做法（可复用）：** 4600 行机械搬移靠手写必然出错，写了一个 TypeScript Compiler API
脚本 `/tmp/ts-split/extract.cjs` 做 AST 级提取：
- 用 `ts.createProgram` + checker 解析，节点必须来自 `program.getSourceFile()`
  （自己 `createSourceFile` 出来的节点喂给 checker 会崩）。
- `this.X` → `this.internals.X` 只在 X 不在同一组时替换，基于
  `PropertyAccessExpression` 节点位置精确替换（不碰字符串里的 `this.`）。
- 共享模块用**传递闭包**自动算出来：从种子集合出发，反复把「被引用且未导出」的
  模块级声明并进来，直到不动点。
- 导入用 checker 解析到声明模块，自动生成 value/type 两类 import。
- 坑：`moduleScopeStatement` 必须在**父节点**上判边界（`ts.isFunctionLike(p)`），
  在自身判会把函数参数当成模块级符号 → 生成一堆垃圾 import。
- 坑：`getFullStart()` 会把前面的类 JSDoc 一起吃进来，要只回退到紧邻的 `/**`。
- 坑：接口方法签名不能用正则去 default value（`visited = new Set<string>()` →
  会产出 `visited?),`），要从 AST 重建签名，推断类型走 checker。
- 搬出去的方法要剥掉 `private `/`protected `；共享模块的声明要补 `export `。

### P1 实现要点（按评审编号）

- **§1 普通 Execution 加 Worker Lease**：新增 `WorkerLeaseService.runWithLease<T>()`
  返回 `{ran:false} | {ran:true;value:T}`。**关键陷阱**：`claim()` 的 WHERE 是
  `lease_expires_at < ?`，对**自己**未过期的租约也返回 false → 嵌套调用（Scheduler
  抢了 → runScheduledExecution → executeMemberTurn 又抢）会把自己当别人，整轮静默
  跳过。解法：`heldByMe()` 短路，本进程已持有就直接跑且**不释放外层租约**。
  `heartbeatMs` 默认 `max(1000, ttl/3)`，新增 `WORKER_LEASE_HEARTBEAT_MS` +
  启动校验 `heartbeat < ttl`（配错一次 = 永久双跑）。
- **§6 三处真缺口**：① `conversation_task` `running→blocked` 无租约条件；
  ② `active_execution_id` 清理漏 `waiting_for_member`（漏了会让单写者保证失效）；
  ③ `queued` root 重提交无保护。注意 `leaseFree('conversation_task','id')` 会**静默
  失效** —— 租约按 execution 抢，Task id 查不到，必须单写
  `leaseFreeTaskExecution()` 指向 `current_execution_id`。
- **§7 wake durable claim**：`LEASE_RESOURCE_WAKE` 常量早就声明、`resetWakeStatuses`
  也早已按它保护，但**全仓没有一处 claim 过 wake 租约**，且 `findLostWakes` 不认租约。
  保护必须加在**「挑」**那一步（挑出来的行会被 index.ts 拿去 redispatch），复位是第二道闸。
  `runWake` **不能**抢 execution 租约（id 是刚 `randomUUID()` 的，抢了也挡不住双跑）。
  wake 租约键 = `conversation_id || ':' || member_id`。
- **§2 Command args 冻结**：新增 `command.args_json TEXT NOT NULL`。`execute(commandId)`
  去掉 args 参数，执行前校验 `hashJson(args) === argsHash`。
- **§3 Command CAS**：`markExecuting(): boolean`（`changes===1`），抢不到抛 409。
  `approve()` 也加 CAS（`WHERE status='policy_pending'`）。
- **§4 Command 幂等竞态**：`INSERT … ON CONFLICT(idempotency_key) DO NOTHING` +
  `changes===0` 回读。**刻意不比对 args**（key 不含 body，同 key 不同 args 是预期内，
  「第一次的 args 胜出」）。
- **§8 Audit append-only**：`policy_decision_audit` 从 `INSERT OR REPLACE` 改成
  `ON CONFLICT(id) DO NOTHING` + 回读 + 逐字段比对，不一致**抛错**。比对**不含
  `created_at`**（含了会让「同一件事记两遍」永远判成不一致）。新增 `command_audit`
  表（业务动作层，与工具层的 policy 决策分开）。`auditCommand()` 必须 try/catch ——
  审计失败不能让业务失败（一条 Jira 评论已发出，抛异常会让调用方以为没执行去重试）。
- **§9 Conversation ACL**：新增 `conversation_participant`（human 进不了
  `conversation_member`，那个 `member_id` 有 FK 指向 `member(id)`）。human 判定 =
  Team active 成员 **且**（participant 或 owner/admin）；agent 仍只看
  `conversation.members`。创建者自动入 participant。`canAccessConversation()` 布尔版
  供批量过滤，`requireAccessToConversation` 是它的否定。
- **§10 OIDC bootstrap owner**：`OIDC_BOOTSTRAP_OWNER_SUB`。`local-user` 永远不出现在
  任何 token 上，拿它建 owner 会让 owner 席位被**无法登录的身份**占着。`hasHumanOwner()`
  区分「全新部署」与「已在跑的部署」。抽到 `server/bootstrap-owner.ts`（index.ts 会

### 踩到的坑

- **`canAccessConversation` 吞掉了 404**：布尔版为了能批量过滤，把「查不到」也归成
  `false`，于是不存在的房间从 404 变成 403。修法：抽出
  `canAccessResolvedConversation(team, req, conversation)` 作为唯一判据，
  `requireAccessToConversation` **先** `getConversation()`（保留 404 语义）再判权限。
  权限判据仍然只有一份。
- **`SCHEMA_SQL` 是模板字符串**：注释里写反引号会提前终止字符串
  （`` -- 是谁做的这件事.`system` `` → `TS1005: ',' expected`）。改用 `「system」`。
- **node:test 的 `describe` 回调在收集阶段就求值**，早于 `before()`。把
  `const base = { executionId }` 写在 describe 体内会钉在空字符串上，表现为
  「每条用例都死在 execution 的外键上」。要写成 `const base = () => ({...})`。
- **测试里手工挂 router 必须自己调 `initTeamScope()`**：`requestTeamId(req)` 在
  `!defaultTeamId || !structure` 时抛 403「Team 尚未初始化」。
  `conversations-api.test.ts` / `conversation-files.test.ts` 都补了这一句。
- **跨用例的租约残留**：前一个用例 claim 出的活租约会让下一个用例的 `claim` 静默
  失败（同资源只有一个 owner），断言变成在测残留状态。加了 `clearLeases()`。
- **`assert.equal(response.status, 200, await response.text())` 会把 body 读掉**
  （参数先求值），成功路径也报 `Body is unusable`。要先判状态再读 body。
