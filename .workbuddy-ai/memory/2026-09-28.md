**关键设计决策：**

1. **不把 45 个 private 成员改成 public**。四个服务不持有 TeamService，而是拿一个
   `TeamInternals` 对象。public 会让 `insertExecution` / `emit` / `transaction`
   这些内部记账变成外部可调 API，恰恰是最不该被碰的。
   `buildInternals()` 里：字段直接读引用，方法用 `bind(this)`（保留泛型签名，
   不用重写类型参数）。
2. **`team-shared.ts` 存在的唯一理由是打断循环依赖**。这些行形状/映射/常量既不属于
   某一个服务，留在 team-service.ts 又会让拆出去的服务反向 import TeamService。
   放中间层，两边都向下依赖。`ExecutionCancelledError` 也一起搬过去，并在
   team-service.ts 里 `export { ExecutionCancelledError } from './team-shared.js'`
   保住原有公开 API。
3. **四个服务彼此不 import**。跨组调用一律走 `internals`（例如 collaboration 用
   `internals.executeMemberTurn`，execution 用 `internals.getConversation`）。
   因此不存在 collaboration ↔ execution 的循环。
4. **`internals` 在构造函数末尾构建**：它按值捕获 db/states/tasks 等字段，那些字段
   在构造过程中才就位。
5. **private 方法搬走后 TeamService 的转发仍保留 private**（runWake /
   executeMemberTurn / buildConfigSnapshot）—— 不然等于顺手扩大了公开 API。

**做法（可复用）：** 4600 行机械搬移靠手写必然出错，写了一个 TypeScript Compiler API
脚本 `/tmp/ts-split/extract.cjs` 做 AST 级提取：
- 用 `ts.createProgram` + checker 解析，节点必须来自 `program.getSourceFile()`
  （自己 `createSourceFile` 出来的节点喂给 checker 会崩）。
- `this.X` → `this.internals.X` 只在 X 不在同一组时替换，基于
  `PropertyAccessExpression` 节点位置精确替换（不碰字符串里的 `this.`）。
- 共享模块用**传递闭包**自动算出来：从种子集合出发，反复把「被引用且未导出」的
  模块级声明并进来，直到不动点。
- 导入用 checker 解析到声明模块，自动生成 value/type 两类 import。
- 坑：`moduleScopeStatement` 必须在**父节点**上判边界（`ts.isFunctionLike(p)`），
  在自身判会把函数参数当成模块级符号 → 生成一堆垃圾 import。
- 坑：`getFullStart()` 会把前面的类 JSDoc 一起吃进来，要只回退到紧邻的 `/**`。
- 坑：接口方法签名不能用正则去 default value（`visited = new Set<string>()` →
  会产出 `visited?),`），要从 AST 重建签名，推断类型走 checker。
- 搬出去的方法要剥掉 `private `/`protected `；共享模块的声明要补 `export `。
