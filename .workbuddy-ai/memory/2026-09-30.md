## 更正：上面第 4 条作废，`Member.description` 保留

上一条把 `description` 列成「可删项」是过头了。**它应该保留**，已经全部还原。

三个字段职责不同，不能互相替代：

| 字段 | 给谁看 | 写什么 | 进 system prompt |
| --- | --- | --- | --- |
| `role` | UI / 路由 / Task assignment | 短职责标签 | 是 |
| `description` | 人 | 职责范围摘要 | **否** |
| `systemPrompt` | 模型 | 工作契约 | 是 |

`description` 出现在 Member 列表 / Profile / picker / Task assignee selector / 搜索筛选里。
**它不是 Persona**，真正该删的是「重复的人格字段」（`Personality` / `Style` / `Soul` / `Bio`）。
约束只有一条：不要被当成主要人格提示，也不要和 `systemPrompt` 重复写一大段。

还原范围：`domain.ts` / `db-migrations.ts`（member 表列）/ `member-service.ts`（7 处）/
`team-service.ts`（本地 MemberRow + conversation-member 投影）/ `routes/members.ts`（create+update 两个 schema）/
`member-template-seeder.ts` / 三个 `config/member-templates/*/member.json` /
`src/lib/api.ts` / `MemberEditor.tsx` / `useWorkspaceActions.ts` / `NewMemberForm.tsx`。

### 为什么「删一列」不是顺手清理

schema 只有「空库才建」这一条路（`migrate()` 对 `from !== 0` 直接 throw，**没有升级代码**），
`SCHEMA_VERSION = 32` 就是形状的唯一身份 —— 同版本号下增删列 = 改形状。
删列之后 `mapRow` 从 `SELECT *` 取 `row.description` 得到 `undefined`，一路传到
`undefined.trim()`；INSERT/UPDATE 也会直接报 `no such column`。
`.data/team-member.db` 实测是 `user_version = 32` **且带该列**、3 行数据，所以还原是向后兼容的、不需要迁移。

已经把「这一列不是装饰」的理由写进 DDL 注释和字段 doc 注释，防第三次。
