### 修复

1. **P0 `PATCH /api/members/:id` 跨 Team 越权**
   - 新增 `TeamService.requireMemberBelongsToTeam(teamId, memberId)`。
     刻意用 `structure.getMembership()`（只查行在不在）而**不是** `requireActiveMembership()`：
     归档会把 membership 置 inactive，用后者会把「恢复归档」和「跨 Team 越权」一起 403 掉，
     Archived Member 再也回不来。
   - `updateMember(id, input, teamId?)`：传了 `teamId` 就必须用传的，不再回落 `defaultTeam()`。
   - `routes/members.ts` PATCH 在写入前校验归属。

2. **P0 member 层能力的 Team 边界**
   - `getMemberCapabilities(teamId, memberId)` / `updateMemberCapabilities(teamId, memberId, ...)`
     服务层各加一次校验；`routes/capabilities.ts` 的 GET/PUT 各加一道，且 PUT 的校验
     **排在 `assignmentsToBindings` 之前**（否则会先拿别人的 Member 去解读 payload）。
   - `deps(teamId)` 把 teamId 透进 catalog 读取。

3. **P1 session 丢失后的 context recovery**
   - `CopilotService.acquireSession` 返回 `{ session, created }`；`runMemberTurn` 返回
     `MemberTurnResult { content, sessionCreated }`。
   - 新增 `persistentSessionExists(sessionId)`：查不出来时按**「不在了」**返回 —— 与
     `isSessionMissing` 的失败方向**相反**（按「还在」处理会静默丢历史；按「不在了」
     最坏是多带一遍房间记录，可恢复）。
   - `ExecutionService` 在 `assemble()` **之前**探针（checkpoint 只在成功那轮写，放在之后
     就来不及），并把 `freshSession` 传给 assembler。
   - `ContextAssembler`：`freshSession` 同时做两件事 —— checkpoint 归零 **且** 关掉
     「过滤自己发过的消息」。只改前者仍会丢这个人自己之前的回答（过滤的前提是
     「它们已在 session history 里」，新 session 里没有）。
   - checkpoint 推进规则：`sessionHoldsEarlierHistory = !result.sessionCreated || freshSession`。
     探针说还在、resume 却发现没了（探针与 resume 之间的窗口）时**退回 0**，让下一轮重放整段。
